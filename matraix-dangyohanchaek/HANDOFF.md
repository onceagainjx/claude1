## 1. 과제 개요

- 목적: 교사 교육철학 프로그램 「당신의 교육철학을 한 권의 책에 담아 드립니다」(「당교한책」, 교육실천이음연구소)를 저경력 교사용으로 바꾼 사이드 프로그램을 만든다. 가칭 「나답게 가르치려 이야기하고 씁니다」.
- 방법: 기존 「당교한책」 6개 여정 40개 질문을 MatrAIx(LLM 페르소나 시뮬레이션, [MatrAIx-ai/MatrAIx-Persona-8B](https://github.com/MatrAIx-ai/MatrAIx-Persona-8B), MIT)로 가상 교사들에게 묻고, 저경력(0~5년)과 고경력(11년 이상)의 반응을 비교한다. 그 결과를 실제 1~2년 차 초등교사 모임 녹취와 대조한 뒤, 사이드 프로그램의 질문 세트와 회차를 설계한다.
- 진행 순서: 시험 실행 → 페르소나 정교화(서울·경기 초등) → 설문·보고서 개편 → 본 실행(300건) → 그래프 → 실제 대화 녹취와 부합성 분석 → 사이드 프로그램 제작 과정 3안 → 3회차 재설계.

## 3. MatrAIx 실행 절차

### 3.1 한 번에 돌리기

```bash
cd matraix-dangyohanchaek
export ANTHROPIC_API_KEY=...            # 또는 MATRAIX_ANTHROPIC_API_KEY
./run_all.sh                            # 6개 여정 × 50명 (경력 5구간 × 10명)
JOURNEYS="1" ./run_all.sh               # 여정 1만
RUN_TAG=v3 ./run_all.sh                 # 같은 설정을 새 job 이름으로 다시 (없으면 이전 job 을 이어서 실행)
```

환경 변수: `MODEL`(기본 `anthropic/claude-sonnet-4-6`), `SAMPLE_SIZE`(기본 50), `MAX_COST_USD`(여정당 상한, 기본 6), `CONCURRENCY`(기본 4), `SEED`(기본 42), `JOURNEYS`, `RUN_TAG`.

### 3.2 `run_all.sh` 가 하는 일

1. 공식 저장소를 `.matraix/` 로 클론하고 `uv sync`
2. Persona 1M 공개 데이터 다운로드: `uv run hf download MatrAIx2026/MatrAIx_Persona_1M_Public_Release --repo-type dataset --local-dir persona/datasets/matraix-persona-1m/release` (최초 1회, 약 6.4 GB)
3. `build_tasks.py` → `application/tasks/dangyohanchaek-j1-…` ~ `j6-…`
4. `build_pool.py --per-bin $PER_BIN --seed $SEED` → `persona/datasets/dangyohanchaek-seoul-gyeonggi-elem-pc10-s42/` (YAML, `manifest.json`, `persona_ids.txt`). 모든 여정에 같은 50명을 쓴다
5. 여정마다:
   - `application/scripts/generate_application_job.py --task … --execution-mode auto --dataset <pool> --persona-ids <50개> --no-strategy --model-name … --n-concurrent-trials 4 --name <job> --job-name <job>`
   - `MATRIX_SURVEY_TASK_PATH=<task> uv run matraix run -c configs/jobs/application-task-job-recipe/<job>.yaml --max-cost-usd 6`
   - `uv run matraix results jobs/<job> --group-by years_experience --format json,csv -o results/<job>`
6. `report.py --jobs <job 폴더들> --out report`

job 이름: `dk-j<n>-kr-elem-pc<구간당 인원>-s<seed>[-<RUN_TAG>]`. 본 실행은 `RUN_TAG=v2`.

### 3.3 알려진 함정과 해결책 (반드시 읽을 것)

| 문제 | 증상 | 해결 |
|---|---|---|
| 공식 1M 인덱스 표집의 `equalTotal` 버그 | `sampleSize` 를 무시하고 구간당 1명만 뽑음 (50명 요청 → 5명) | `perCell` 로 구간당 인원을 직접 지정. 지금은 `build_pool.py` 가 칸(경력 × 성별)별로 처리 |
| 포함 필터만 받는 표집기 | `company_size` 같은 값으로 거르면 값이 없는 페르소나까지 빠짐 | `build_pool.py` 가 칸마다 후보를 전부 가져온 뒤(칸당 상한 `MAX_SAMPLE_SIZE/5`) 파이썬에서 제외 조건을 적용 |
| 응답 언어 | 페르소나 프롬프트의 "use your primary language" 때문에 설문 v1에서 서술 23%가 비한국어 | `lang_korean=Native` + `primary_language=Korean` 페르소나만 사용하고, 과제 안내에 한국어 강제. `report.py` 가 비한국어 서술을 세어 '[한국어 아님]' 표시 |
| 검증기 시간 초과 | 응답은 만들어졌는데 verifier 가 120초를 넘겨 실패 | `task.toml` 의 verifier `timeout_sec = 600` (`build_tasks.py` 반영됨) |
| 백그라운드 실행 2시간 제한 | Claude Code 의 백그라운드 명령은 최대 2시간. 전체 6개 여정은 약 6시간 | 여정을 하나씩 따로 실행 (`JOURNEYS="3" RUN_TAG=v2 ./run_all.sh`). 같은 job 이름으로 다시 돌리면 Harbor 가 이어서 실행 |
| 끊긴 trial 이 완료로 처리됨 | 중단 시 실행 중이던 trial 이 이어서 실행할 때 끝난 것으로 남아 `survey_result.json` 이 없음 | 결과 수를 job 마다 세어 확인하고, 빠진 페르소나만 재실행 (3.4) |
| 모델 JSON 오류 | 본 실행 300건 중 2건이 `JSONDecodeError` | 실패한 페르소나만 재실행 (3.4) |
| API 크레딧 부족 | `HTTP 400 credit balance is too low` 로 대량 실패 | 충전 후 `RUN_TAG` 를 바꿔 새로 실행 |
| `set -e` 와 `read` | 줄바꿈 없는 입력에 `read` 가 실패 코드를 내 스크립트가 멈춤 | `mapfile -t persona_ids < persona_ids.txt` 사용 (반영됨) |
| 보고서 덮어쓰기 | `run_all.sh` 끝의 `report.py` 가 `report/` 를 그 실행분으로 덮어씀 | 일부 여정만 돌릴 때는 커밋 전에 `git checkout -- report/` 로 되돌리거나 다른 `--out` 으로 다시 만들 것 |
| 실행 시간 | trial 당 응답 약 66초 + 검증 약 118초, 동시 4개 | 50명 여정 하나에 약 1시간 |
| 경로 함정 | MatrAIx 백엔드 모듈을 직접 쓸 때 import 실패 | `PYTHONPATH=<.matraix>:<.matraix>/application/playground` |

### 3.4 실패한 페르소나만 다시 돌리기 (본 실행에서 쓴 방법)

```bash
cd .matraix
export ANTHROPIC_API_KEY="${MATRAIX_ANTHROPIC_API_KEY:-$ANTHROPIC_API_KEY}"
POOL=persona/datasets/dangyohanchaek-seoul-gyeonggi-elem-pc10-s42
task=$(ls -d application/tasks/dangyohanchaek-j1-* | head -1)
job=dk-j1-kr-elem-pc10-s42-v2-retry
uv run python application/scripts/generate_application_job.py --task "$task" --execution-mode auto \
  --dataset $POOL --persona-ids <실패한 persona_id ...> --no-strategy --seed 42 \
  --model-name anthropic/claude-sonnet-4-6 --n-concurrent-trials 2 --name $job --job-name $job
MATRIX_SURVEY_TASK_PATH="$task" uv run matraix run -c configs/jobs/application-task-job-recipe/$job.yaml --max-cost-usd 1
cd .. && uv run python report.py --jobs .matraix/jobs/dk-j{1,2,3,4,5,6}-kr-elem-pc10-s42-v2 \
  .matraix/jobs/dk-j{1,3}-kr-elem-pc10-s42-v2-retry --out report
```

실패한 페르소나 찾기: job 폴더의 각 trial 에서 `result.json` 의 `exception_info` 가 있거나 `survey_result.json` 이 없는 것을 고르고, `persona_meta.json` 의 `persona_id` 를 읽는다.

## 4. 페르소나 설계 (`build_pool.py`)

- 필터(스키마 속성): `role_function=Teaching`, `region=East Asia`, `lang_korean=Native`, `life_stage` 가 학생·은퇴가 아닌 것.
- 제외(가져온 뒤): `company_size` 가 `Solo / freelance`(학원·과외 강사로 보임) 또는 `Academia`(대학 강사), `primary_language` 가 Korean 이 아닌 것.
- 표본: 경력 5구간(0-2, 3-5, 6-10, 11-20, 20+) × 구간당 10명. 목표 남 30% : 여 70%. 후보가 모자란 칸은 다른 성별로 채움. 결과적으로 3-5년 구간만 남 7 : 여 3, 전체 남 19 : 여 31.
- 덧붙인 속성(overlay, `manifest.json` 의 `overlay_dimensions`): 학교급 = 초등학교(전원), 근무 지역 = 서울·경기(칸마다 반반, 25 : 25). 성별에 맞춘 한국식 이름으로 `display_name` 교체.
- 한계: 페르소나에는 국가 속성이 없고, 덧붙인 속성은 페르소나 설명 끝의 'Other attributes' 에 한 줄로 들어갈 뿐이다. 원래 이야기(전공, 근무 기관)와 어긋날 수 있다.
- 참고: 사용자가 처음 고른 방식은 "B. 같은 페르소나를 복제해 비교하기 → 복제 없이 나누어 붙이기"(서울·경기 반반)였다.

## 5. 설문 설계 (`build_tasks.py`, 설문 v2)

- 여정마다 Survey 과제 1개, 총 6개.
- 원 질문마다 세 문항: 서술형 원 질문 → '답하기 쉬움' 1~10점 → '어려웠던 가장 큰 이유' 단일 선택 + 이유 서술(rationale).
  - 이유 선택지: `lack_experience`(경험 부족), `premise_mismatch`(전제 불일치), `too_personal`(사적·감정적), `too_abstract`(추상적), `survival_first`(생존 우선), `no_difficulty`(어렵지 않음).
- 여정 평가: 의미 / 심리적 부담 / 시기 적절성 (모두 1~10점), 5년 차 이하용 질문 수정안, 지금 다루고 싶은 이야기.
- 안내: 서술과 이유는 반드시 한국어로. 프로필의 학교급·근무 지역을 실제 근무 환경으로 삼아 답하기.
- 보고서 6장 구성: 1 여정별 요약과 질문별 분석 / 2 재설계 우선순위와 저경력 대표 이유 2개 / 3 이유별로 어느 질문에서 골랐는지 / 4 저경력 목소리(질문 수정 제안, 질문별 어려움의 이유) / 5 저경력이 다루고 싶은 이야기 / 6 같은 질문에 대한 저경력·고경력 응답 비교.

- 저경력 '답하기 쉬움' 최고점은 5-2 현재의 마음 8.9, 최저점은 6-6 여정의 의미 5.95(앞선 여정을 겪었다는 전제 탓일 가능성).
- 해석 주의: LLM 시뮬레이션이다. 재설계 가설용이고, 실제 교사 파일럿으로 확인해야 한다.

## 7. 실제 저경력 교사 대화와의 부합성 분석

자료: 1~2년 차 초등교사 모임 1회차 녹취(약 1시간 30분). 진행자 2명(경력이 긴 교사)을 빼고 발언이 분명한 저경력 5명(A, D, E, F, G)을 근거로 썼다. D는 녹취에 '중학교'로 들리는 부분이 있으나 초등 교사로 확인했다. 모임 질문은 「당교한책」이 아니라 그 모임의 질문(꿈, 좋아하는 것과 교실에서 하는 일, 교실 안의 나의 뒷모습)이어서 주제가 같은 발언을 대응시켰다. 전문은 `report/transcript_comparison.html`.

- 판정: 직접 근거 16개, 부분 근거 11개, 분석 불가 13개. 세부 판정은 부합 15, 대체로 부합 5, 간접 부합 1, 판단 보류 3, 불일치 3, 분석 불가 13개.
- 맞는 부분: 경험담 질문은 실제로도 쉬웠다(1-2~1-5, 2-2, 2-3, 4-2~4-5, 5-2, 5-3, 6-2). 4-6은 이유까지 같았다(원인을 '아직 저연차여서', '제가 미성숙해서'로만 봄). 추상적 질문에는 답이 짧아졌다.
- 맞지 않는 부분 (모두 시뮬레이션이 실제보다 어렵게 봄):
  - 3-1: '기억에 남는 아이'는 실제로 매우 쉬웠다(작년 제자와 그 아이의 지금 소식). '졸업한 아이 소식'만 어렵다.
  - 2-1: 지금 아이들이 나를 어떻게 보는지는 쉽게 말했다. '시간이 지난 후' 가정만 어렵다.
  - 6-4(6-6도 가능성): 페르소나가 대화를 겪지 않고 가정으로 답한 설계 탓일 수 있다. 실제로는 대화 직후 쉽게 답했다.
- 시뮬레이션이 놓친 점: 글쓰기·출판 부담("한 문장 한 문장 더 부담돼", "교직논술이 오히려 더 쉬웠을 것"), 대화 효과(동료 이야기가 생각을 끌어냄).
- 분석 불가 영역: 여정 3 사회와 미래(3-2~3-6), 4-1, 2-6, 5-6, 5-7, 6-3, 6-5, 6-7.

## 8. 사이드 프로그램 기획: 「나답게 가르치려 이야기하고 씁니다」(가칭)

### 8.1 사용자가 준 기획 방향과 전제

- 기획 방향: 「당교한책」 질문 세트를 수정·통합·삭제·확장해 새 질문 세트를 만든다. 저경력 교사의 선호에 맞게 세부 사항을 바꾼다. 6회차를 줄여 가볍게 만든다. 호기심과 참여 동기를 돋우는 장치(제목의 힙함 등)를 둔다.
- 키워드: 교육철학 → 나답게 가르치기. '자기 네러티브' = 나는 이곳에 왜 있고 무엇을 하고자 하는가(자기 동기)를 구체적으로 풀어 가는 것.
- 새 가정: 기존 「당교한책」은 참여 교사에게 문제의식과 쌓인 경험이 있다고 전제한다. 저경력은 교실 경험이 몇 번뿐이라, 힘든 일이 있으면 학교가 마냥 힘든 곳이 되고 좋은 경험으로 시작하면 마냥 좋은 곳이 된다(인식이 케바케).
- 공동체 영역: 당신의 네러티브와 나의 네러티브가 만나는 지점에서 공동의 목표를 정의한다.
- 일에 의한 소진에서 벗어나기.
- 나답게 일하기 7가지 원리와 핵심 질문:
  1. 자신의 욕구를 들여다보기
  2. '무슨 일'보다 '왜'에서 시작하기 — 나는 왜 이 일을 하고 있는가?
  3. 외부의 성과보다 자신의 동기에서 목표 세우기 — 외부가 요구하는 성과인가, 내가 만들고 싶은 변화인가?
  4. 자신을 일과 동일시하지 않기 — 나는 이 일을 주체적으로 하는가, 삶을 유지하기 위한 도구가 되었는가?
  5. 자신의 몫과 타인의 몫 구분하기 — 지금 내가 감당하는 책임은 정말 나의 몫인가?
  6. 타인과 함께 일하는 방식을 새로 만들기 — 나답게 가르치면서 다른 사람들과 함께 성장하고 있는가?
  7. 완성이 아니라 계속 찾아가는 과정 — 지금 일하는 방식은 내가 원하는 삶과 일치하는가?

### 8.2 제작 과정 3안 (제안함)

- A. 질문 세트 리모델링: 40문항을 근거로 유지·수정·통합·삭제·확장해 3회차, 약 15문항으로 압축(약 6~7주). 예: 3-1 → "작년에 가르친 아이 중 기억에 남는 아이는? 그 아이는 지금 어떻게 지내나요?", 2-1 → "지금 우리 반 아이들은 나를 어떤 선생님이라고 말하나요?", 1-6 → "교실에서 나는 ○○하는 사람이다", 4-6 → 나/아이들/학교 관점을 나눠 묻기, 6-1 → 1~3년 차가 쓴 여는글. 삭제·선택: 3-2~3-6, 4-1, 2-6, 6-3~6-6.
- B. 개념 우선 재설계: 7가지 원리를 뼈대로 하고, 「당교한책」 질문을 원리마다 '장면 질문(입구)'으로 고쳐 쓴다(약 7~8주).
- C. 공동 설계: 1~3년 차 5~8명의 설계단과 질문 카드 50장, 실험 모임 2회로 질문·형식·이름을 함께 정한다(약 8~10주).
- 추천: B를 뼈대로, A의 근거로 문구를 다듬고, C의 실험 모임 1회로 검증(약 8주).
- 공통 형식 제안: 3회(한 학기, 월 1회) + 선택 1회, 회당 2시간(대화 80분, 짧은 글 20분, 정리 20분), 3명 조, 1~3년 차가 쓴 여는글, 회차마다 '3문장 기록', 마지막에 한 쪽 '나답게 가르치기 선언'을 모아 얇은 진(zine).
- 참여 동기 장치: 제목 후보 「쌤로그(Ssam-log)」, 「N년차 나 사용설명서」, 「나답쌤 클럽」, 「왜 쌤이 됐냐면요」(부제는 「나답게 가르치려 이야기하고 씁니다」). 모임 전 '이번 주 교실 한 컷' 장면 카드, 질문 카드 뽑기(피할 권리 포함), 동료 짝, 마지막 회차 선언문과 '1회차의 나에게 쓰는 편지'.

### 8.3 3회차 재설계 (최신안)

사용자 피드백: 처음 안의 2회차("지속 가능한 나": 성과·일과 나·나의 몫)는 이미 소진된 교사, 자신을 잃을 위기의 교사에게 맞는 인상을 준다. 그래서 2회차를 '회복'이 아니라 '나다운 일의 방식을 처음부터 설계하기'로 바꿨다. 질문에는 '소진', '희생', '벗어나기' 같은 단어를 쓰지 않는다.

| 원리 | 기존 표현 (회복의 말) | 저경력용 표현 (설계의 말) |
|---|---|---|
| 3 | 성과에 쫓겨 의미를 잃음 | 잘한다는 기준을 누가 정하는지 살펴보기 |
| 4 | 소진, 자신을 잃음 | 교실 속 나의 온도와 거리 정하기 |
| 5 | 과도한 책임에서 벗어나기 | 내가 붙잡을 것과 맡겨 둘 것 고르기 |

| 회차 | 주제 | 원리 | 핵심 질문 |
|---|---|---|---|
| 1회 | 나다움의 출처: 나는 왜 여기 있을까 | 1, 2 | 나는 교실에서 무엇을 할 때 가장 나다운가? |
| 2회 | 교실 속 나의 온도: 나다운 일의 방식 고르기 | 3, 4, 5 | 나는 교실에서 어떤 온도와 거리로 있고 싶은가? |
| 3회 | 이야기가 만나는 곳: 함께, 그리고 계속 | 6, 7 | 너와 나의 이야기는 어디서 만나고, 나는 다음 학기에 무엇을 실험해 볼까? |

회차별 질문 15개:

- 1회
  1. 여는 장면: 교사가 되기로 한 장면 하나를 떠올려 보세요. (「당교한책」 1-2·1-3 변형)
  2. 잇는 장면: 이번 학기 교실에서 시간 가는 줄 몰랐던 순간과, 유난히 길게 느껴졌던 순간을 하나씩 꺼내 보세요. (케바케 대응: 좋은 장면과 힘든 장면을 짝으로)
  3. 의미: 그 두 순간에 나는 각각 무엇을 원하고 있었나요? (원리 1)
  4. 핵심: 나는 교실에서 무엇을 할 때 가장 나다운가요? "교실에서 나는 ○○하는 사람이다"로 써 보세요. (원리 2, 1-6 개선)
  5. 3문장 기록: 내가 교사가 된 이유와, 지금 교사로 있는 이유는 같은가요, 달라졌나요?
- 2회
  1. 여는 장면: 최근 아이들과 너무 가깝다고, 혹은 너무 멀다고 느낀 장면이 있나요? (원리 4)
  2. 교실에서의 나와 교실 밖의 나는 얼마나 닮았나요? 닮게 두고 싶은 것과 다르게 두고 싶은 것은? (원리 4)
  3. 요즘 '잘하고 있다'고 느끼게 하는 기준은 무엇인가요? 그 기준은 누가 정했나요? (원리 3)
  4. 바라는 교실과 실제 교실이 달랐던 장면에서, 나의 몫, 아이들의 몫, 시간에 맡겨 둘 몫은 각각 무엇이었나요? (원리 5, 4-5·4-6 개선)
  5. 핵심 + 3문장 기록: 나는 교실에서 어떤 온도와 거리로 있고 싶은가요? 다음 한 달 동안 시험해 볼 '나만의 온도 규칙' 하나를 정해 보세요.
- 3회
  1. 여는 장면: 2회차의 '온도 규칙'을 한 달 동안 해 보니 어땠나요? (원리 7)
  2. 잇는 장면: 올해 나를 버티게 하거나 웃게 한 동료의 한마디가 있나요? (원리 6, 5-3·6-2 변형)
  3. 의미: 오늘 들은 이야기 가운데 내 이야기와 겹치는 지점은 어디였나요? (원리 6)
  4. 핵심: 너와 나의 이야기는 어디서 만나나요? 그 지점에서 우리가 함께 해 볼 수 있는 일은? (원리 6)
  5. 마무리 글: 1회차의 나에게 쓰는 편지. 지금의 나는 무엇을 알게 되었고, 다음 학기에 무엇을 실험해 볼까요? (원리 7, 6-6을 경험 뒤에 묻는 형태)

근거가 된 실제 대화 발언: "선생님은 난로처럼 거리가 있어야 된다고"(G), "조금은 온도 조절을 하려고"(A), "기대를 낮춰야 되는데 저는 그게 기대가 항상 높았나 봐요"(G), "포커페이스의 존재로 있으려다 보니"(G).

## 10. 작업 방식에 관한 메모

- 사용자는 한국어로 짧고 구체적인 답을 선호한다. 결과 파일(HTML)은 스크립트 없이 열리게 만든다 (사용자의 보기 프로그램이 스크립트를 막았다).
- 그래프·보고서 HTML은 밝은/어두운 화면과 휴대폰 폭에서 확인한다 (Playwright: `executablePath:'/opt/pw-browsers/chromium'`, 전역 `playwright` 패키지).
- 큰 결과물은 커밋하기 전에 비밀값(`sk-ant-`, `ANTHROPIC_API_KEY=`)이 없는지 확인했다.
- 커밋은 작업 브랜치 `claude/quirky-lovelace-c9j1v9` 에만 했다. PR은 만들지 않았다.
